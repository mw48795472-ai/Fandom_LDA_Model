# 실루엣 게이트 정책 (Silhouette Gate Governance) — 정리 및 검증

## 이 문서가 다루는 것

"실루엣 게이트"는 `v7_final_10020/docs/METHODOLOGY.md` 4절("실루엣 게이트 거버넌스")이 정의하는
이 프로젝트의 핵심 품질 관리 규칙이다. 이 문서는 라운드별 코퍼스 규모·실루엣·K·M을 정리한
실측 타임라인 `data/silhouette_gate_timeline/corpus_silhouette_timeline_v7_66_2ch.csv`(v4 종료∼v7 r66 2차)와
최종 코퍼스(10,020건) 시점의 참고 재적합 결과를 근거로, 이 정책이 실제로 어떻게 적용되었는지를
재정리하고 저장소의 다른 파일과 교차검증한다.

## 정책 정의 (원문, `docs/METHODOLOGY.md` 4절)

1. **실루엣 게이트**: 새 K→M 재군집화 결과가 기존 채택 스냅샷의 실루엣 계수를 넘지 못하면
   자동 기각. 매 라운드 실제 재계산값만 사용(센티널 값 금지).
2. **동결 스냅샷**: 검증된 v7-40 스냅샷(7,350건, K=10, M=5, silhouette=0.267)을 해석 계층
   (토픽 명명·F 배정·페르소나 분류)의 고정 기준선으로 삼는다.
3. **이원 구조**: 라이브 코퍼스는 별도 트랙으로 계속 증량하되(최종 10,020건), 보조지표(7개 지수)
   계산에만 반영하고 해석 계층에는 반영하지 않는다.
4. **정직한 한계 기록**: v7-41 이후의 재적합 라운드가 전부 기각됨(최종 보고서 v7-77 시점 기준
   누적 28회 연속)을 숨기지 않고 그대로 보고서 본문에 명시했다.

즉 코퍼스(근거문장)는 계속 리서치로 늘려가되, "토픽 이름표(F1∼F5)를 다시 붙이는 재해석"은
**새 실루엣이 v7-40의 0.267을 넘어설 때만** 허용한다는 규칙이다. 코퍼스를 키우는 것과
해석 계층을 갱신하는 것을 의도적으로 분리한 거버넌스다.

상관계수 r=+0.15 — 사실상 무관). 최종 코퍼스 10,020건 시점의 참고 재적합(K=8, M=5)은 0.046으로
이 구간의 최저치보다도 낮다. "코퍼스를 더 모으면 언젠가 실루엣이 기준선을 넘을 것"이라는
가정은 이 프로젝트에서 실측으로 뒷받침되지 않으며, `docs/METHODOLOGY.md`가 "정직한 한계
기록"으로 이 사실을 숨기지 않고 그대로 보고한 이유이기도 하다.

전 구간으로 넓혀 보면 방향은 오히려 음(−)이다. 실측 31개 지점만으로는 r=−0.42, 선형보간
추정치까지 포함한 66개 지점으로는 r=−0.61이다(보간 행은 실측이 아니므로 후자는 참고값). 즉
v5(2,359건, 0.233)·v7-40(7,350건, 0.267)처럼 높은 실루엣이 나온 시점은 코퍼스 크기가 아니라
토크나이저·로스터 구성이 바뀐 시점과 겹친다.

또한 K/M 조합이 라운드마다 계속 바뀐다는 점(K=8/M=5가 가장 흔하지만 K=12/M=8, K=10/M=5,
K=8/M=6, K=10/M=6, K=12/M=7도 등장)도 그대로 드러난다 — 코퍼스가 조금만 바뀌어도 실루엣
최댓값 탐색이 다른 K/M 조합을 고르는 "K→M 재군집화 불안정성"이 게이트 구간에서 동일하게
반복된다.

## 적용된 코드 — `build_silhouette_gate_timeline_v7.py`

같은 폴더의 `build_silhouette_gate_timeline_v7.py`는 위 CSV로 이중축 타임라인 차트(코퍼스 규모 vs
실루엣)를 그리는 matplotlib 스크립트다. 이 프로젝트의 다른 차트 스크립트와 동일한 관례(헤드리스
렌더링, NotoSansCJKkr 폰트, PNG+SVG 저장, `output/charts/`)를 따르며, 그리기 전에 위 표의
검증값(게이트 구간 라운드 수·상관계수·성장률·동결 스냅샷 값)을 코드 안에서 직접 재계산해
콘솔에 출력하는 자체 무결성 체크를 포함한다. 게이트 구간의 끝은 CSV의 마지막 실측 라운드로
자동 결정되므로, 이후 라운드가 CSV에 추가되면 표시 구간도 함께 늘어난다. 라운드별 세부 라벨은
가독성을 위해 핵심 지점(v4 종료·v7 39/40 동결 기준선·r46 게이트 시작·마지막 실측)만 표시한다.

## 개편안 (v2, 2026-09-23 채택)

단일 실루엣 임계(0.267, 시드 하나의 한 번 값) 대신 (G1) 시드 ≥10개 실루엣 중앙값 ≥ 재현 가능한 현직 모델의 중앙값, (G2) 시드 쌍 토픽 Jaccard 중앙값 ≥ 0.35, (G3) 시드별 최적 M 합의, (G4) 현직 기준값의 재현 가능성 — 을 요구하는 안이다. L7의 측정치로 네 적합에 적용하면 v1로는 전부 기각, v2로는 라이브 K=8만 통과하며, 현직으로 삼은 동결 근사 재적합 K=10조차 M=5가 시드 합의가 아니라는 점(G3 실패)이 드러난다. `GATE_POLICY_V2_PROPOSAL_V7.md`·`gate_policy_v2_v7.py`·`gate_policy_v2_decisions_v7.json`. **v2는 채택됐다.** 루트 README 4·5절의 해석 계층은 통과 모델(라이브 K=8)의 값으로 바뀌었고, 위 '정책 정의' 절의 v1 규칙과 최종 보고서 PDF의 동결 해석 계층은 그 시점의 기록으로 남긴다.

**v2.1 (2026-09-23 채택) — 텍스트 품질 수정 라운드.** 코퍼스 건수를 바꾸지 않고 기존 근거의 언어·표기만 고치는 라운드(예: 영문으로 수집된 근거를 한국어로 재작성)는 새 모델 후보가 아니라 **현직 모델의 재측정**으로 본다. 이런 라운드에는 G1(현직 중앙값 비교)을 적용하지 않고, G2(시드 Jaccard)·G3(M 합의)·G4(재현성)만 확인한 뒤 채택한다. 근거: 수정분이 시드 분포 폭 안에 있는 실루엣 차이를 만들 수 있는데, 그것으로 수집 언어 편향의 교정을 막으면 게이트가 데이터 오류를 고정하는 도구가 된다. 첫 사례가 **r73**(투어스(TWS) 영문 근거 86건 한국어 재작성, 순증 0, `data/v7_rounds/round_log_r73.json`)이다: r73 K=8 시드 중앙값 0.081(r72 0.102)로 G1은 미달이지만 Jaccard 0.425·M 합의 통과로 채택했고, 루트 README 4·5절의 해석 계층은 r73 재적합(K=8, M=5 고정, seed 0 실루엣 0.092; 페르소나 현장상업형 89·글로벌투어형 8·집단동원형 2·산업확장형 1)의 값이다(`analysis/persona_decision_space/live_interpretive_layer/`, r72 계층은 `live_interpretive_layer_r72/`). 재적합으로 K→F 배정이 바뀌어(출연·예능과 브랜드·광고 토픽이 미디어노출형 하나로 합쳐짐) 페르소나 분포가 r72(62/17/12/9)와 크게 달라졌다는 점은 이 계층의 불안정성으로 README 5절에 그대로 적었다.

## 한계

1. **선형보간 구간의 실루엣 추정치는 실측이 아니다.** CSV 자체가 "[추정·선형보간]"으로 (그리고 `측정구분` 열로 실측 31행 / 추정·선형보간 37행 / 코퍼스만 39행을 구분해)
   명시하고 있으며, 구 토크나이저가 일관되게 쓰인 구간(v5∼r27, r29∼r34)과 신 토크나이저 구간
   (v7 40∼r45 1차)에서만 양 끝 실측값 사이를 선형으로 이은 것이다. v7 38∼39라운드 사이(토크나이저
   개편) 등 방법론이 바뀐 지점은 보간하지 않는다(실측점만 점선으로 직접 연결).
2. **`r45(1차)`(K=12, M=2)와 `r45(3차, 롤백진단)`(구 토크나이저+코퍼스 일부 롤백)는 같은
   "r45"라는 라운드 번호를 공유하지만 서로 다른 방법론으로 측정된 값**이라 CSV의 "비고"
   컬럼이 이렇게 경고하고 있다 — 두 값을 같은 시점의 재실행 반복으로 오독하면 안 된다.
3. 타임라인 CSV의 r22 행(5,613건)은 `merge_log_r22.json`의 로그 산술(`5606+7`)을 따른 값이며,
   당시 평탄화 코퍼스 실제 건수와 1건 차이가 있다. 최종 코퍼스 10,020건 집계에는 영향이 없다.
4. 이 문서는 타임라인 CSV와 저장소의 진단 JSON이 서술하는 내용을 재정리·재검증한 것이다.
   저장소의 `run_lda_v6.py`는 K→M 재군집화·실루엣 계산 파이프라인 자체를 포함하지만, 최종
   참고 재적합(0.046)을 만든 14개 언어 라우팅 토크나이저 판(`run_lda_v6_live_reference_v7.py`)은
   원본이 없어 각 라운드의 실루엣 값을 이 저장소만으로 재계산하지는 못한다. 다만 저장소 루트의 같은 이름
   재구성본으로 최종 코퍼스를 돌리면 K=8 선택은 재현되고 M·실루엣은 6·0.081(원본 5·0.046)로 근방값이 나온다
   (`analysis/tokenizer/live_reference_tokenizer/TOKENIZER_RECONSTRUCTION_V7.md` 5절). 게이트 기각(0.267 미달)이라는 결론은 같다.
5. 게이트 기준선 0.267 자체는 재현되지 않은 값이다. 동결 근사 코퍼스(7,326건)와 재구성 토크나이저로 K=10을 다시 적합하면
   M=5 실루엣이 0.07에 그친다(`analysis/persona_decision_space/topic_phi_cosine/frozen_v7_40/FROZEN_MODEL_REFIT_V7_40.md`).
